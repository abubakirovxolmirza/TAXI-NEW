# Руководство по подтверждению заказов

## Обзор новой логики

Система обработки заказов была обновлена для улучшения процесса принятия и подтверждения заказов водителями.

### Основные изменения

1. **Без ограничения по времени отображения**
   - Заказы теперь отображаются в списке для водителей без ограничения по времени
   - Ранее заказы исчезали из списка через 5 минут после создания
   - Теперь они остаются доступными до тех пор, пока их не примет водитель

2. **Двухэтапный процесс: Принятие → Подтверждение**
   - **Принятие заказа**: Водитель выбирает заказ из списка
   - **Подтверждение заказа**: У водителя есть 15 минут для подтверждения принятого заказа

3. **Автоматический возврат неподтвержденных заказов**
   - Если водитель не подтверждает заказ в течение 15 минут, заказ автоматически возвращается в общий список
   - Водитель может также вручную отклонить заказ, вернув его в общий список

## Новые API endpoints

### 1. Подтверждение заказа
```http
POST /api/driver/orders/confirm/{order_type}/{order_id}
```

**Параметры:**
- `order_type`: `taxi` или `delivery`
- `order_id`: ID заказа

**Описание:**
- Подтверждает принятый заказ
- Должно быть выполнено в течение 15 минут после принятия
- После подтверждения заказ полностью закрепляется за водителем

**Ответ:**
```json
{
  "success": true,
  "message": "Order confirmed successfully",
  "order": {
    "id": 123,
    "type": "taxi",
    "status": "accepted",
    "is_confirmed": true,
    "confirmed_at": "2024-11-18T12:00:00Z"
  }
}
```

### 2. Отклонение заказа
```http
POST /api/driver/orders/reject/{order_type}/{order_id}
```

**Параметры:**
- `order_type`: `taxi` или `delivery`
- `order_id`: ID заказа

**Описание:**
- Отклоняет принятый, но не подтвержденный заказ
- Возвращает заказ в общий список для других водителей
- Можно использовать только для неподтвержденных заказов

**Ответ:**
```json
{
  "success": true,
  "message": "Order rejected and returned to pending list",
  "order": {
    "id": 123,
    "type": "taxi",
    "status": "pending"
  }
}
```

### 3. Обновленный endpoint принятия заказа
```http
POST /api/driver/orders/accept/{order_type}/{order_id}
```

**Изменения:**
- Удалена проверка 5-минутного ограничения
- Теперь заказы можно принимать в любое время после их создания
- После принятия устанавливается `is_confirmed = false`

## Поток работы

### Для водителя

1. **Просмотр доступных заказов**
   ```
   GET /api/driver/orders/new
   ```
   - Получить список всех PENDING заказов (без временных ограничений)

2. **Принятие заказа**
   ```
   POST /api/driver/orders/accept/taxi/123
   ```
   - Заказ переходит в статус ACCEPTED
   - Устанавливается `accepted_at` timestamp
   - `is_confirmed = false`
   - У водителя есть 15 минут для подтверждения

3. **Подтверждение заказа (в течение 15 минут)**
   ```
   POST /api/driver/orders/confirm/taxi/123
   ```
   - Устанавливается `is_confirmed = true`
   - Устанавливается `confirmed_at` timestamp
   - Заказ полностью закрепляется за водителем

4. **Или отклонение заказа**
   ```
   POST /api/driver/orders/reject/taxi/123
   ```
   - Заказ возвращается в статус PENDING
   - Становится доступным для других водителей

5. **Завершение заказа**
   ```
   POST /api/driver/orders/complete/taxi/123
   ```
   - Теперь требует подтверждения (`is_confirmed = true`)
   - Переводит заказ в статус COMPLETED

### Для пассажира

Пассажир получает уведомления о следующих событиях:

1. **Заказ принят** - когда водитель принимает заказ
2. **Заказ подтвержден** - когда водитель подтверждает заказ (в течение 15 минут)
3. **Заказ возвращен** - если водитель отклоняет или не подтверждает заказ вовремя
4. **Заказ завершен** - когда водитель завершает выполнение

## Новые поля в базе данных

### taxi_orders и delivery_orders

```sql
confirmed_at TIMESTAMP WITH TIME ZONE NULL     -- Время подтверждения заказа
is_confirmed BOOLEAN NOT NULL DEFAULT FALSE    -- Подтвержден ли заказ
```

## Фоновая задача

Система автоматически запускает фоновую задачу, которая:
- Проверяет каждую минуту все принятые, но неподтвержденные заказы
- Возвращает в PENDING статус заказы, которые не были подтверждены в течение 15 минут
- Уведомляет водителя и пассажира о возврате заказа
- Делает заказ снова доступным для всех водителей

## Примеры использования

### Пример 1: Успешный флоу
```
1. Пассажир создает заказ → PENDING
2. Водитель видит заказ в списке (без временных ограничений)
3. Водитель принимает заказ → ACCEPTED, is_confirmed=false
4. Через 5 минут водитель подтверждает → is_confirmed=true
5. Водитель завершает поездку → COMPLETED
```

### Пример 2: Водитель отклоняет
```
1. Пассажир создает заказ → PENDING
2. Водитель принимает заказ → ACCEPTED, is_confirmed=false
3. Водитель передумал и отклоняет → PENDING (доступен другим)
4. Другой водитель принимает → ACCEPTED, is_confirmed=false
5. Водитель подтверждает → is_confirmed=true
6. Завершение → COMPLETED
```

### Пример 3: Автоматический возврат
```
1. Пассажир создает заказ → PENDING
2. Водитель принимает заказ → ACCEPTED, is_confirmed=false
3. Водитель не подтверждает в течение 15 минут
4. Система автоматически возвращает → PENDING (доступен другим)
5. Другой водитель видит заказ в списке и может принять
```

## Важные замечания

1. **Подтвержденные заказы нельзя отклонить** - после подтверждения водитель должен завершить заказ
2. **Завершить можно только подтвержденный заказ** - это гарантирует, что водитель осознанно взял заказ
3. **Фоновая задача работает каждую минуту** - проверяет истечение 15-минутного окна
4. **Все изменения статуса отправляются через WebSocket** - для real-time обновлений

## Тестирование

### Тест 1: Базовый флоу
```bash
# Создать заказ
curl -X POST http://localhost:8000/api/taxi-orders/ \
  -H "Authorization: Bearer <user_token>" \
  -H "Content-Type: application/json" \
  -d '{ ... }'

# Принять заказ
curl -X POST http://localhost:8000/api/driver/orders/accept/taxi/1 \
  -H "Authorization: Bearer <driver_token>"

# Подтвердить заказ
curl -X POST http://localhost:8000/api/driver/orders/confirm/taxi/1 \
  -H "Authorization: Bearer <driver_token>"

# Завершить заказ
curl -X POST http://localhost:8000/api/driver/orders/complete/taxi/1 \
  -H "Authorization: Bearer <driver_token>"
```

### Тест 2: Отклонение заказа
```bash
# Принять заказ
curl -X POST http://localhost:8000/api/driver/orders/accept/taxi/1 \
  -H "Authorization: Bearer <driver_token>"

# Отклонить заказ
curl -X POST http://localhost:8000/api/driver/orders/reject/taxi/1 \
  -H "Authorization: Bearer <driver_token>"

# Проверить, что заказ снова PENDING
curl -X GET http://localhost:8000/api/driver/orders/new \
  -H "Authorization: Bearer <another_driver_token>"
```
