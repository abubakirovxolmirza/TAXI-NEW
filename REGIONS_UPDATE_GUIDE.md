### 2. Создание заказов без авторизации

Теперь пользователи могут создавать заказы такси и доставки **без регистрации и авторизации**.

#### Что изменилось:

**Файлы изменены:**
- `app/auth.py` - добавлена функция `get_optional_user()` для опциональной аутентификации
- `app/utils.py` - добавлена функция `get_or_create_guest_user()` для автоматического создания гостевых пользователей
- `app/routers/taxi_orders.py` - endpoint `POST /api/taxi-orders/` теперь работает без токена
- `app/routers/delivery_orders.py` - endpoint `POST /api/delivery-orders/` теперь работает без токена

#### Как это работает:

1. **С токеном (авторизованный пользователь):**
   - Заказ создается для существующего пользователя
   - Все данные берутся из токена

2. **Без токена (гостевой пользователь):**
   - Система проверяет, существует ли пользователь с указанным номером телефона
   - Если пользователь найден - заказ создается для него
   - Если пользователь не найден - создается новый гостевой аккаунт с указанными данными
   - Гостевой пользователь может позже войти в систему, создав пароль через регистрацию

#### Примеры API запросов:

**Создание такси заказа без токена:**
```bash
POST /api/taxi-orders/
Content-Type: application/json

{
  "username": "Иван Иванов",
  "telephone": "+998901234567",
  "from_region_id": 1,
  "from_district_id": 1,
  "to_region_id": 2,
  "to_district_id": 15,
  "passengers": 2,
  "date": "20.11.2025",
  "time_start": "14:00",
  "time_end": "16:00"
}
```

**Создание доставки без токена:**
```bash
POST /api/delivery-orders/
Content-Type: application/json

{
  "username": "Алиса Смирнова",
  "sender_telephone": "+998901234567",
  "receiver_telephone": "+998907654321",
  "from_region_id": 1,
  "from_district_id": 1,
  "to_region_id": 3,
  "to_district_id": 5,
  "item_type": "document",
  "date": "20.11.2025",
  "time_start": "10:00",
  "time_end": "12:00"
}
```

## Важные замечания

1. **Миграция БД:** Не требуется! Структура таблиц `regions` и `districts` уже правильная (создана в начальной миграции). Скрипт `update_regions.py` только обновляет данные.

2. **Безопасность:** Хотя создание заказов доступно без авторизации, все остальные операции (просмотр истории, отмена заказов и т.д.) требуют авторизации.

3. **Гостевые пользователи:** Создаются автоматически с ролью `USER` и случайным паролем. Пользователь может позже зарегистрироваться с тем же номером телефона.

4. **Обновление регионов:** После запуска скрипта обновления все существующие регионы будут удалены. Убедитесь, что нет активных заказов, привязанных к старым регионам, или выполните миграцию данных.

## Проверка работы

После внесения изменений:

1. Запустите скрипт обновления регионов
2. Проверьте API документацию: `http://localhost:8000/docs`
3. Протестируйте создание заказов без токена
4. Убедитесь, что создаются гостевые пользователи в базе данных

## Откат изменений

Если нужно вернуть требование авторизации:

1. В `app/routers/taxi_orders.py` замените `get_optional_user` на `get_current_user`
2. В `app/routers/delivery_orders.py` замените `get_optional_user` на `get_current_user`
3. Удалите логику создания гостевых пользователей из функций создания заказов
