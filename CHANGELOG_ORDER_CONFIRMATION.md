# Сводка изменений: Новая логика подтверждения заказов

## Дата: 18 ноября 2024

## Описание
Обновлена логика обработки заказов такси и доставки для улучшения процесса принятия и подтверждения заказов водителями.

## Основные изменения

### 1. Модели данных (app/models.py)
**Добавлены новые поля в TaxiOrder и DeliveryOrder:**
- `confirmed_at` - DateTime, nullable - время подтверждения заказа водителем
- `is_confirmed` - Boolean, default=False - флаг подтверждения заказа

### 2. Схемы (app/schemas.py)
**Обновлены схемы ответов:**
- `TaxiOrderResponse` - добавлены поля `confirmed_at` и `is_confirmed`
- `DeliveryOrderResponse` - добавлены поля `confirmed_at` и `is_confirmed`

### 3. Роутеры водителя (app/routers/driver.py)

#### Изменен endpoint принятия заказа:
- **Удалено:** 5-минутное ограничение для принятия заказов
- **Теперь:** Заказы можно принимать в любое время после создания
- **Изменение:** При принятии устанавливается `is_confirmed = False`

#### Добавлены новые endpoints:

**POST /api/driver/orders/confirm/{order_type}/{order_id}**
- Подтверждение принятого заказа
- Должно быть выполнено в течение 15 минут после принятия
- Устанавливает `is_confirmed = True` и `confirmed_at`
- При истечении 15 минут возвращает заказ в статус PENDING

**POST /api/driver/orders/reject/{order_type}/{order_id}**
- Отклонение принятого, но не подтвержденного заказа
- Возвращает заказ в статус PENDING
- Делает заказ доступным для других водителей
- Нельзя отклонить подтвержденный заказ

#### Обновлен endpoint завершения заказа:
- **Добавлена проверка:** Завершить можно только подтвержденный заказ
- **Требование:** `is_confirmed = True`

### 4. Фоновые задачи (app/tasks.py) - НОВЫЙ ФАЙЛ

**Функция check_unconfirmed_orders():**
- Запускается каждую минуту
- Проверяет заказы в статусе ACCEPTED с `is_confirmed = False`
- Если прошло более 15 минут после `accepted_at`, возвращает заказ в PENDING
- Уведомляет водителя и пассажира о возврате заказа
- Оповещает всех водителей через WebSocket о доступности заказа

**Функция start_background_tasks():**
- Инициализирует и запускает все фоновые задачи

### 5. Главный файл (main.py)
- Добавлен импорт `from app.tasks import start_background_tasks`
- В функции `lifespan` добавлен вызов `start_background_tasks()`
- Фоновые задачи запускаются при старте приложения

### 6. Миграция базы данных (alembic/versions/add_order_confirmation_fields.py) - НОВЫЙ ФАЙЛ

**Миграция:** add_order_confirmation
- Добавляет колонку `confirmed_at` в таблицы `taxi_orders` и `delivery_orders`
- Добавляет колонку `is_confirmed` в таблицы `taxi_orders` и `delivery_orders`
- Поддерживает откат (downgrade)

## Новая логика работы

### Было:
1. Заказ создается → PENDING
2. Заказ доступен водителям только 5 минут
3. Водитель принимает → ACCEPTED
4. Водитель завершает → COMPLETED

### Стало:
1. Заказ создается → PENDING
2. Заказ доступен водителям **без ограничения по времени**
3. Водитель принимает → ACCEPTED (`is_confirmed = False`)
4. У водителя есть **15 минут** для подтверждения
5. Водитель подтверждает → `is_confirmed = True`
   - ИЛИ отклоняет → заказ возвращается в PENDING
   - ИЛИ не подтверждает вовремя → автоматически возвращается в PENDING
6. Водитель завершает → COMPLETED (только после подтверждения)

## WebSocket события

### Новые события для водителей:
- `order_returned` - заказ возвращен в общий список

### Новые события для пассажиров:
- `order_confirmed` - заказ подтвержден водителем

## Требования к деплою

```bash
alembic upgrade head
```

### 2. Перезапустить приложение
Фоновые задачи запустятся автоматически при старте

### 3. Проверить логи
Должно быть сообщение: `[TASKS] Background tasks started`

## Обратная совместимость

- Все существующие endpoints продолжают работать
- Старые заказы (без `confirmed_at` и `is_confirmed`) будут работать корректно
- Миграция устанавливает значение по умолчанию `is_confirmed = false` для существующих записей

## Тестирование

### Минимальный набор тестов:
1. Создать заказ и проверить, что он доступен без временных ограничений
2. Принять заказ и подтвердить его в течение 15 минут
3. Принять заказ и отклонить его (проверить возврат в PENDING)
4. Принять заказ и не подтверждать 15+ минут (проверить автоматический возврат)
5. Попытаться завершить неподтвержденный заказ (должна быть ошибка)
6. Попытаться отклонить подтвержденный заказ (должна быть ошибка)

## Зависимости

Новых зависимостей не добавлено. Используются существующие:
- FastAPI
- SQLAlchemy
- asyncio (стандартная библиотека Python)

## Известные ограничения

1. Фоновая задача проверяет заказы каждую минуту - точность ±1 минута
2. При большом количестве заказов (>10000) может потребоваться оптимизация запросов
3. Фоновая задача не сохраняет состояние при перезапуске - заказы проверяются заново

## Что дальше?

3. Штрафные баллы для водителей, часто отклоняющих заказы
